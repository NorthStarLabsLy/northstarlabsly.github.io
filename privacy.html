How the utility handles information

Privacy Policy

This policy describes the owner-operated RED CENT Backup utility and this information website. It does not describe the wider RED CENT application.

Last updated: 7 November 2026

Google Drive access and purpose

The utility uses the owner's Google account to store and retrieve private encrypted backup archives in a designated Drive destination. The configured permission is drive.file, which limits access to specific files created by or made accessible to the app. It does not request full-Drive access.

The permission supports creating, reading, modifying and deleting app-accessible files. A configured destination identifies where the utility operates; it is not a separate OAuth permission boundary.

Backup contents and encryption

Backup archives contain RED CENT's collected data and supporting history, evidence, manifests and operational state. rclone encrypts archive contents, filenames and directory names before uploading them to Google Drive.

Encryption does not hide all metadata, such as stored object sizes or transfer activity. The computer or worker processing a backup can access the local archive and the secrets available to that process. Encryption is not a guarantee against compromise or loss.

OAuth credentials and crypt recovery secrets are kept separately from the data archives. The rclone configuration is password-encrypted. This website does not receive those credentials, recovery secrets or archive contents.

Transfers and service providers

The configured archive destination is the owner's Google Drive. Google processes account, storage and request information as the Drive provider under its own policies.

The prepared worker design uses Render to run the backup process and Healthchecks for backup-status monitoring. A deployed worker would process local archive data and credentials on its host, upload encrypted archives to Drive, and send monitoring status metadata, including archive identifiers and verification timestamps. This description does not assert that the worker or monitoring is deployed.

The backup workflow does not publish archives through this information site or offer public access to the owner's Drive destination.

Retention and deletion

The prepared trial policy retains a baseline plus up to seven verified daily backup copies in Drive. Remote snapshots are not automatically deleted by the backup retention workflow, so this is not a promise that information is erased after seven days.

Local cleanup applies to generated backup archives under the worker's verification and storage-capacity rules. It does not establish a fixed retention period for the source data or all local copies.

The owner controls removal of remote archives and separately retained recovery material. Removing an archive from one location does not remove copies elsewhere or change Google's storage and deletion practices.

Account control and recovery

The owner can revoke the utility's access through the backup Google account's third-party access controls. Revocation prevents future authorised access; it does not itself delete existing backup files.

Recovery depends on retaining access to the backup account, the encrypted configuration and the separate unlocking and crypt recovery secrets. Google access tokens and refresh tokens may expire or be revoked.

This website

These pages contain no JavaScript, analytics, advertising, forms, cookies or tracking code. They load no third-party fonts or libraries.

If published on GitHub Pages, the hosting provider may process request information independently of these pages. GitHub states that it logs visitors' IP addresses for security. This site does not claim that hosting produces no logs.
